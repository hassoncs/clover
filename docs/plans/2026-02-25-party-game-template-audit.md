# Party Game Template & Content Audit (2026-02-25)

## 1. Strict Taxonomy Definitions

To ensure consistency across the platform, we define three distinct layers of game identity:

| Layer | Definition | Example |
|---|---|---|
| **Template (Mechanic)** | The immutable engine-level logic, UI flow, and networking code. Lives in `r2/games/party/`. | `quiplash` |
| **Content Type** | The data schema generated by AI or pulled from the database. Lives in the `ContentType` enum. | `quip` |
| **Brand-Specific Title** | The user-facing name, theme, and skin. Defined in `packages/brands/`. | "The Fellowship Table" |

## 4. Scaling Strategy: The 8-Brand Expansion

To scale this taxonomy to the 8 new white-label verticals, we recommend a **Manifest-Driven Architecture**.

### The 8 New Brands:
1. **Corporate Team Building**
2. **Wedding/Event Entertainment**
3. **Bar Trivia / Restaurant Games**
4. **Sports Fan Games**
5. **Holiday/Seasonal Packs**
6. **Education / Classroom**
7. **Kids Birthday Parties**
8. **Senior Living / Retirement**

### Implementation Recommendations:

1. **Brand Registry**: Centralize all brand titles in `packages/brands/src/registry.ts`.
2. **Dynamic Prompting**: The `ContentType` should remain generic, but the `BrandId` must be passed to the AI generator to inject the correct tone and domain knowledge (e.g., "Generate `trivia` for `senior-living` focusing on 1950s-70s pop culture").
3. **Template Aliasing**: Allow a single `Template` to have multiple `Titles` within a brand. For example, the `Corporate` brand might use `quickfire-qa` for both "Compliance Quest" and "Industry Insights".
4. **Theme Injection**: Use the `BrandTheme` to automatically apply visual skins (colors, fonts, asset packs) to the generic templates at runtime.
