### Root Cause of Skia Init Failure (Key Insight)
`@shopify/react-native-skia/lib/module/skia/Skia.web.js` runs this at module load time:
```js
export const Skia = JsiSkApi(global.CanvasKit);
```
If `global.CanvasKit` is `undefined` at import time, `Skia` is permanently broken for that module instance. Storybook's per-story loaders in `preview.ts` run **after** module imports — so the async CanvasKit init arrives too late.

**The fix**: `WithSkiaWeb` from `@shopify/react-native-skia/lib/module/web` wraps the component in a `React.lazy()` that calls `LoadSkiaWeb()` first, then dynamically imports the inner component. Because the dynamic import happens after `LoadSkiaWeb()` resolves, `global.CanvasKit` is set when `Skia.web.js` first runs for that lazy chunk.

### `WithSkiaWeb` API
```tsx
<WithSkiaWeb
  getComponent={() => import("./MySkiaComponent").then(m => ({ default: m.MySkiaComponent }))}
  componentProps={propsObject}
  fallback={<div>loading…</div>}
/>
```
Located at: `@shopify/react-native-skia/lib/module/web` (compiled JS, not in main package index).

This is fine for the design system display use case.
