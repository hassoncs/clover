Drift Detection Verification for Task 5.

The baseline test `registry-baseline.test.ts` is designed to detect the following drifts during the migration:

1. Template Count Drift:
   - Assertion: `expect(templateIds).toHaveLength(20)`
   - Catches: Accidental deletion or addition of templates in `registry.ts`.

2. Template ID Naming Drift:
   - Assertion: `expect(canonicalTemplateIds).toContain(id)`
   - Catches: Renaming of template IDs before the coordinated migration in Wave 3.

3. Content Type Drift (The "Wager/History" Sentinel):
   - Assertion: `expect(contentPacks).not.toContain("wager")`
   - Assertion: `expect(contentPacks).not.toContain("history")`
   - Catches: 
     - New templates using the old "wager" or "history" naming.
     - Existing templates (except year-jinx) regressing to old naming.
     - Verification of T9 fix: Once T9 is applied, the special case for `year-jinx` in the test should be removed to ensure it stays clean.

4. Structure Drift:
   - Assertion: `toHaveProperty("party")`, `toHaveProperty("contentPacks")`
   - Catches: Breaking changes to the `PartyGameDefinition` structure during refactoring.
