# T10: Non-canonical key rejection proof

## How unknown/non-canonical keys are rejected

### 1. base-configs.ts — BASE_CONTENT_CONFIGS record

`wager` and `history` keys have been removed from `BASE_CONTENT_CONFIGS`.
Canonical keys remaining: quip, trivia, fibbage, drawing, ranking, headsup,
dilemma, wordlist, personal, wyr, estimation, caption, wordgame, chroma.

Any caller of `composeGameTypeConfig(brandId, gameType)` passing "wager" or
"history" will now throw:
  > Unknown game type: wager. Available: quip, trivia, fibbage, ...

Because `prompts.ts` → `composeGameTypeConfig` does:
  const baseConfig = BASE_CONTENT_CONFIGS[gameType];
  if (!baseConfig) {
    throw new Error(`Unknown game type: ${gameType}. Available: ...`);
  }

### 2. brand-content-config.ts — getGameTypeConfig

`wager` and `history` keys removed from both amen and slopcade brand configs.
Replaced with single `estimation` key (targetCount: 500).

Any call to `getGameTypeConfig(brandId, "wager")` will now throw:
  > Unknown game type "wager" for brand "amen". Available: quip, trivia, ...

### 3. brands.ts — BrandTheme.categories

`wager` and `history` category arrays merged into single `estimation` array
in both amenBrand and slopcadeBrand.

Looking up `brand.categories?.["wager"]` now returns undefined (no entry),
which causes `buildPromptOverlay` to omit the CATEGORY CONSTRAINTS section
for "wager" — correctly steering generation through "estimation" only.

### 4. readable-text.ts — getReadableText switch

`case "wager":` removed. Content stored as type "wager" in the DB falls to
the `default:` branch (returns body.text). Canonical "estimation" content
continues to use `case "estimation":` → body.question.

Legacy DB rows with content_type="wager" are handled by LEGACY_ALIASES in
prompt-loader.ts (maps estimation → ["wager", "history"]) until T16 removes
that alias after DB migration.
