## T7: Fallback Hit Path

### Function: loadContentPackFromDB (api/src/party/content/prompt-loader.ts)

Fallback path (primary canonical type returns 0 rows):

1. Caller invokes `loadContentPackFromDB("estimation", brandId, db)`.

2. Primary D1 query executes with `content_type = "estimation"`.
   `result.results` is empty — no migrated rows exist yet (pre-T8 state).

3. `rows.length === 0`, so the fallback block is entered.

4. `LEGACY_ALIASES["estimation"]` resolves to `["wager", "history"]`.

5. `console.warn` fires:
   ```
   [party-content] No "estimation" content for brand "<brandId>".
   Falling back to legacy aliases: wager, history.
   Run DB migration to normalize content types.
   ```

6. Alias iteration begins:
   a. Query for `content_type = "wager"` — if rows found, return them immediately.
   b. If `wager` also empty, query for `content_type = "history"` — if rows found, return them.

7. If all aliases also return 0 rows, falls through to the original `throw new Error(...)`.

### When this path fires:
- DB has NOT been migrated yet (T8 not run) — rows still stored as `wager`/`history`.
- Canary state: fallback hits in logs indicate migration is still needed.

### Observable signal:
- `[party-content] No "estimation" content...` warning appears in Cloudflare Worker logs.
- Presence of these warnings is the signal that T8 (DB migration) should be run.
- Absence of warnings after T8 confirms it is safe to remove the fallback (T16).

### Removal gate:
- TODO(T16): Remove LEGACY_ALIASES and fallback block after zero-hit confirmation.
- Zero-hit = no `[party-content]` warnings in logs after T8 migration deploys.
