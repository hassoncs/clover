================================================================================
NEGATIVE SCENARIOS (HIGH-RISK GAPS)
================================================================================

--- Gap #1: expo-font installed but never used ---
SCENARIO: A game author sets `fontFamily: "PressStart2P"` on an overlay text element.
RESULT: React Native renders the text in the platform default font (San Francisco on iOS,
Roboto on Android). The game looks nothing like the author intended. The Godot layer
renders the correct font (if a URL was also provided), creating a visual mismatch between
game-world text and overlay text.
IMPACT: Every game using custom fonts has broken overlay typography. Authors cannot
achieve consistent branding across game + UI layers.

--- Gap #2: FontPreset type defined, not implemented ---
SCENARIO: A game definition includes `fontPreset: "pixel"` in its OverlayTheme.
RESULT: The preset string is stored but never resolved to a font file or URL. Both
Godot and RN ignore it. The game renders in system fonts despite the author explicitly
requesting a pixel aesthetic.
IMPACT: The FontPreset feature is a dead API — it promises functionality that doesn't
exist. Authors who discover it will file bugs or lose trust in the editor.

--- Gap #3: No bundled game fonts ---
SCENARIO: A user plays a game on a subway (no network). The game definition references
a Google Fonts URL for its title font.
RESULT: Godot's TextEffectSystem HTTP request fails. The fallback is ThemeDB.fallback_font
(a generic sans-serif). The game's visual identity is lost. If the game was designed
around a pixel font for readability at small sizes, the fallback font may be harder to
read at the same size.
IMPACT: Offline play degrades visual quality unpredictably. No way for authors to
guarantee their font choices are honored.

--- Gap #5: fontFamily passthrough without loading ---
SCENARIO: A game definition sets `fontFamily: "Bangers"` on a score counter overlay.
RESULT: OverlayRenderer.tsx passes "Bangers" to React Native's fontFamily style prop.
Since the font was never loaded via expo-font, RN cannot find it. On iOS, this silently
falls back to San Francisco. On Android, it falls back to Roboto. On web, the browser
may attempt a CSS font-family lookup and fail similarly.
IMPACT: The fontFamily field on overlay elements is effectively non-functional for any
non-system font. This is the most user-visible gap — it affects every game that tries
to use custom typography in overlays.
