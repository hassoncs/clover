## Learned Rules
1. **T6 (notepads/memory)**: Nearly always deletable after task completion. Extract insights first.
2. **T5 (plans)**: Delete immediately when all checkboxes are checked AND code verified. Code is the documentation.
3. **T4 (evidence)**: Temporary artifacts - delete after task completion.
4. **Checkbox counting**: Use `grep -c "^- \[x\]"` and `grep -c "^- \[ \]"` to verify completion status.
5. **Batch deletions**: Group files by tier and purpose before asking for confirmation.
6. **Skill extraction**: Docs with code examples + gotchas are prime skill candidates.
7. **Skill categories**: Map doc location to skill category for consistent organization.
8. **Cross-linking**: Always link related skills to improve discoverability.
9. **Supersession detection**: Look for "v1/v2", "revised", "updated" in titles, and check dates.
10. **Party games rule (UPDATED)**: Delete plans for games that are BUILT (code = documentation). Keep plans for unbuilt games as roadmap.
11. **Worktree awareness**: Always verify `pwd` and use explicit absolute paths or `workdir` parameter.
12. **Learnings extraction ROI**: Most notepad learnings.md files are empty or trivially captured in code. Sample before bulk processing.
13. **False positive checkboxes**: A plan with 100% checked boxes may still be incomplete if the implementation took a different path.
14. **Reference vs Plan distinction (NEW)**: Many "plans" are actually reference docs (catalogs, style guides, feasibility studies, architecture specs). These should live in `docs/`, not `.sisyphus/plans/`. A plan must have actionable tasks to stay in plans/.
15. **Speculative plan lifecycle (NEW)**: Plans with 0 progress after 14+ days should be deleted aggressively. Git has history. Re-creating a plan from scratch is often better than maintaining stale specs.
16. **Consolidation delegation (NEW)**: When consolidating docs into skills, spot-check the subagent's work — verify the appended content is accurate and not duplicated.
17. **Worktree debt (NEW)**: Fleet worktrees and stale feature worktrees accumulate. Next run should prune `.worktrees/` directory.
18. **Party game filename matching (NEW)**: r2/games/party/ directory names don't always match plan filenames exactly (e.g., `open-mic-frenzy` plan exists but game may be registered differently). Cross-reference via manifest.json game IDs, not just directory names.
