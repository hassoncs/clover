# Workflow Optimization Report

Date: 2026-03-10 16:10:37
Project: `slopcade`
Focus: Pencil web Skia startup-boundary debugging

## Applied Now

### 1. Pencil web startup-boundary memory

- problem: We repeatedly rediscovered that Expo Router eagerly evaluates `app/` route modules on web, which made Skia import poisoning easy to reintroduce.
- evidence: The debugging loop only stabilized after moving Skia-reachable imports out of `apps/pencil/app/` and into a route-local lazy boundary.
- observed facts: `apps/pencil/app/webgl-probe.tsx` loaded cleanly once the route tree was Skia-free; the main Pencil route rendered again after moving the boundary to `apps/pencil/components/PencilCanvasPanel.web.tsx`.
- inferred cause: The repo lacked a durable project memory artifact explaining the exact safe boundary.
- proposed improvement: Add a project skill and AGENTS.md note for Pencil web Skia boundaries.
- expected benefit: Future agents should avoid repeating the same import-order debugging loop.
- risk: Low.
- scope: Project docs/skills only.
- action: apply-now.

### 2. Browser harness tie-breaker

- problem: Ghost Browser reported page crashes that did not match the real app state, which prolonged the debugging loop.
- evidence: Ghost reported crashes while Playwright verified that `webgl-probe` and then the main Pencil route loaded successfully.
- observed facts: Shared-session state and Ghost crash reporting were misleading during startup debugging.
- inferred cause: The default browser workflow docs lacked an explicit fallback verifier for suspicious crash reports.
- proposed improvement: Document "Ghost first, Playwright second" in the global AGENTS and project skill.
- expected benefit: Faster separation of real app failures from browser-harness/session artifacts.
- risk: Low.
- scope: Global workflow docs.
- action: apply-now.

### 3. OpenCode config path clarity

- problem: Local-vs-global skill/config locations were still easy to confuse across OpenCode and Claude compatibility paths.
- evidence: The global `opencode-configuration` skill was too short and omitted the current dual-directory conventions.
- observed facts: The live plugin uses `~/.config/opencode/skills/`, while Claude-compatible docs/skills still exist in `~/.claude/`.
- inferred cause: The config skill had drifted behind the real machine state.
- proposed improvement: Expand the config skill with explicit path tables and compatibility notes.
- expected benefit: Less routing/search friction when users ask to add skills or update agent docs.
- risk: Low.
- scope: Global skill docs.
- action: apply-now.

## Deferred

### 1. Automated guardrail for route imports

- problem: The startup-boundary bug can be reintroduced by new imports in `apps/pencil/app/`.
- evidence: The debugging session identified route-level imports as the real regression vector.
- observed facts: We discussed lint/build enforcement but did not finish a tested guardrail in this learning pass.
- inferred cause: The protection still lives in documentation rather than tooling.
- proposed improvement: Add a TDD-backed lint/build rule that forbids `@shopify/react-native-skia` and `@slopcade/design-canvas` imports under `apps/pencil/app/`.
- expected benefit: Regression prevention at CI time.
- risk: Medium, because it touches lint/build tooling and needs tests.
- scope: Project tooling.
- action: record-for-later.
